# TT-Agent-Plus-727 世界书过滤、数据路由与失败审核设计

## 1. 背景

当前插件已经能够监听酒馆原生 `WORLDINFO_SCAN_DONE` 事件，读取本轮实际激活的世界书条目，按 Token 上限拆分任务，并把成功加工的缓存注入最终提示词。

本设计在该链路上增加三项能力：

1. 针对当前角色卡自带世界书创建可复用的条目级包含/排除规则。
2. 让每个子 AI 预设自由选择输入、输出目标和原始条目策略。
3. 让并发任务在失败时进入统一审核流程，全部解决后再交给 TT 原生流式生成。

核心链路如下：

```text
酒馆原生世界书命中
→ 当前角色卡世界书限定
→ 条目处理规则（包含/排除）
→ 子 AI 预设与 Token 分批
→ 全局调度器并发执行
→ 成功结果路由 / 失败审核
→ 所有分支汇合
→ 处理原始条目并注入结果
→ TT 原生流式生成
```

## 2. 范围

### 2.1 本次范围

- 世界书命中继续来自酒馆原生 `WORLDINFO_SCAN_DONE`，插件不重复实现关键词扫描。
- 配置页面自动读取当前角色卡自带世界书及其完整条目列表。
- 每条世界书处理规则支持“包含”或“排除”一种模式。
- 世界书处理规则可以被多个子 AI 预设复用。
- 子 AI 预设可以显式读取其他 AI 的版本化数据。
- 子 AI 结果可以同时路由到多个目标。
- 失败支持人工优先或 AI 优先审核。
- 所有审核操作使用同一个审核弹窗。
- 审核弹窗手动关闭后显示顶部灵动岛，待审核事项清空后自动隐藏。

### 2.2 暂不支持

- 不提供自定义世界书选择器。
- 不让一条世界书处理规则同时配置多本世界书。
- 不因数据写入自动触发其他 AI；后续任务仍由调度器显式创建。
- 不修改酒馆原始世界书文件或给条目写入插件标签。

## 3. 数据来源

插件使用两个相互独立的数据入口。

### 3.1 配置阶段

通过 ST/TT 宿主上下文读取当前角色卡及其自带世界书，再读取该书的完整条目列表。宿主差异封装在 `CharacterWorldInfoRepository` 适配器中，业务层只依赖以下能力：

```js
{
  getActiveCharacterRef(),
  getCharacterWorldRef(characterRef),
  listWorldEntries(worldRef)
}
```

UI 不展示世界书选择器。世界书标识由适配器自动解析并锁定。

### 3.2 运行阶段

插件监听 `WORLDINFO_SCAN_DONE`，读取 `eventData.activated.entries`。现有标准化结果已经包含 `world`、`uid`、`displayName`、`content` 和 `sourceHash`。

运行时只处理同时满足以下条件的条目：

1. 条目由酒馆本轮实际激活。
2. 条目属于当前角色卡自带世界书。
3. 条目通过子 AI 所绑定的世界书处理规则。

酒馆同时激活的全局世界书、角色备注或其他世界书不进入本次条目过滤链路。

## 4. 世界书处理规则

世界书处理规则是独立、可复用的配置，不等同于子 AI 提示词预设。

```js
{
  id: '01',
  name: '角色组',
  worldRef: '角色卡世界书稳定标识',
  mode: 'include',
  entryUids: ['1', '2', '5', '8'],
  version: 1
}
```

条目使用 `worldRef + uid` 作为稳定身份，显示序号和条目名称只用于 UI。条目改名但 UID 不变时规则继续有效；UID 已不存在时标记为失效选择。

### 4.1 包含模式

只把“本轮命中集合”和“规则条目集合”的交集交给子 AI。

```text
本轮命中：1、2、3、4、5、6、7、8
规则包含：1、2、5、8
最终输入：1、2、5、8
```

包含模式未选择任何条目时，最终输入为空。

### 4.2 排除模式

从本轮命中集合中扣除规则条目集合，再把剩余条目交给子 AI。

```text
本轮命中：1、2、3、4、5、6、7、8
规则排除：6、7
最终输入：1、2、3、4、5、8
```

排除模式未选择任何条目时，最终输入为全部命中条目。

### 4.3 默认与迁移

系统提供不可删除的“全部条目”内置规则。现有默认子 AI 预设迁移后绑定该规则，保持升级前处理全部命中条目的行为。用户也可以为子 AI 选择“不读取世界书”。

## 5. 条目规则 UI

现有“规则”页面增加两个二级视图：

```text
[子 AI 预设] [世界书处理规则]
```

世界书处理规则页面顶部只读显示当前角色和角色卡世界书。编辑器包含：

- 规则名称。
- “包含 / 排除”分段控件。
- 条目搜索框。
- 全选、反选操作。
- 条目名称、UID、启用状态和按需展开的正文预览。
- 当前搜索结果已选数量、整本世界书已选数量和最终允许读取数量。

搜索和批量选择遵循以下规则：

- 全选和反选只作用于当前搜索结果。
- 已选择但被搜索条件隐藏的条目保持原状态。
- 清空搜索后，全选和反选作用于整本世界书。
- 搜索结果为空时禁用全选和反选。

桌面端使用列表与侧边编辑区；安卓窄屏使用面板内全宽编辑页，不叠加小尺寸浮窗。当前角色没有自带世界书时显示明确空状态并禁用创建按钮。

## 6. 子 AI 预设

每个子 AI 本质上是用户可编辑的提示词预设。插件只提供一份默认模板和组合能力，不规定预设必须扮演角色、世界观、变量维护或其他具体职责。

子 AI 预设在现有字段基础上增加：

```js
{
  worldInfoRuleId: '01',
  inputStoreRefs: [],
  outputRoutes: [],
  sourcePolicy: 'replace_on_success',
  failureReviewerAiId: null
}
```

### 6.1 输入

- 当前角色卡世界书经过处理规则后的命中条目。
- 用户显式授权读取的其他 AI 当前数据版本。
- 父任务分配的资料和补充说明。

默认不允许子 AI 读取其他 AI 数据。跨 AI 读取必须在预设中显式配置。

### 6.2 输出路由

输出目标是多选而不是单选。每个路由记录 `required`，用于声明该目标失败时是否继续阻塞本轮汇合。同一次成功结果可以同时：

- 保存到自己的数据区。
- 写入指定其他 AI 的数据区。
- 注入 TT 最终提示词。
- 写入插件面板。
- 写入聊天框。
- 仅供下级任务读取。

数据写入不会自动触发新的 AI。子任务和下级任务必须由调度器创建，继续受全局并发、Token 上限、最大深度、总派发次数、额度审核和防递归规则约束。

处理结果满足以下条件时才算该预设成功：worker 已成功结束，且所有 `required` 输出路由均已成功。若没有必需路由，worker 成功即视为预设成功。启用 TT 注入时，该路由默认是必需路由；用户可以显式改为非必需。

### 6.3 原始条目策略

每个预设提供两个明确选项：

- `keep_original`：保留酒馆原始条目，处理结果按输出路由追加。
- `replace_on_success`：预设满足上述成功条件后移除原始条目，处理结果按输出路由发送。

默认模板使用 `replace_on_success`，延续“世界书只作为子 AI 加工原料”的核心设计。

多个子 AI 对同一条目给出冲突策略时采用“保留优先”。冲突必须写入 Debug，列出条目、预设和最终决策。

## 7. 版本化 AI 数据

每个 AI 拥有独立命名空间。写回其他 AI 时生成新版本，不不可逆覆盖旧数据。

```js
{
  storeOwnerAiId: 'ai-a',
  producerAiId: 'ai-b',
  version: 4,
  parentVersion: 3,
  status: 'current',
  taskId: 'task-123',
  content: {},
  createdAt: 0
}
```

成功写回时：

1. 创建新版本。
2. 原当前版本变为历史版本。
3. 新版本成为当前版本。
4. UI 提供版本查看和回滚入口。

维护 AI 可以同时写回目标 AI，并在自己的数据区保存维护指南。每个路由独立记录成功、失败和重试状态。

## 8. 并发与汇合屏障

世界书过滤完成后，各子 AI 任务在全局并发限制内异步执行。单个任务失败不暂停其他任务。

最终 TT 生成前设置汇合屏障。只有所有相关任务进入以下终态之一，才组装最终上下文并继续 TT 原生流式生成：

- 成功完成。
- 重 Roll 后成功。
- AI 审核后成功。
- 用户跳过。
- 用户取消整轮生成。

关闭审核弹窗不代表跳过，未解决任务继续处于 `awaiting_review`，汇合屏障继续等待。

宿主事件适配器必须验证 `WORLDINFO_SCAN_DONE` 监听器可以被宿主异步等待。若目标宿主无法等待该事件，插件必须禁用自动汇合模式并显示兼容性错误，不能假装已经阻止最终请求。

## 9. 失败审核

任务失败时保留以下失败包：

```js
{
  taskId: 'task-123',
  sourceRefs: [],
  workerPresetId: 'ai-a',
  partialResult: null,
  error: {},
  attempts: [],
  reviewState: 'awaiting_review'
}
```

失败不会移除原始世界书条目，也不会覆盖任何 AI 的当前数据版本。失败部分结果、错误和每次尝试一律追加到失败历史，作为不可变审核记录保留。失败历史与 AI 当前数据版本分离；只有审核后成功的结果才能按预设路由创建新的当前版本。

### 9.1 审核优先级

全局设置提供：

- `human_first`：失败后直接进入人工审核。
- `ai_first`：先交给指定失败审核 AI，无法解决时再进入人工审核。

AI 审核仍通过全局调度器，受并发、Token、额度确认和最大深度约束。失败审核 AI 再次失败后必须进入人工审核，不允许在失败处理链路中无限递归。

另提供“AI 审核时自动弹窗”开关：

- 开启：AI 审核开始时打开审核弹窗并展示实时状态。
- 关闭：AI 在后台审核，只有仍需人工处理时才强制打开弹窗。

### 9.2 统一审核弹窗

API 派发确认、失败任务和其他需要用户决定的事项进入同一个审核弹窗。弹窗按类型分区，但不创建新的页面入口。

失败条目展示：

- 世界书条目名称和 UID。
- 使用的子 AI、预设和模型。
- 失败原因和阶段。
- 已尝试次数。
- 每次重 Roll 的时间、模型、补充说明和错误。
- 可展开的失败部分结果。

逐条操作：

- `重 Roll`：使用原预设重新运行。
- `补充说明重 Roll`：把用户补充说明加入本次尝试后重新运行。
- `跳过`：结束该分支并保留酒馆原始条目。

批量操作：

- `全部重 Roll`。
- `全部跳过`。
- `取消本轮生成`。

每次重 Roll 创建新的尝试记录，不覆盖旧记录。成功后再按预设的输出路由和原始条目策略执行。

## 10. 审核灵动岛

审核弹窗被用户手动关闭且仍有待审核事项时，在屏幕顶部安全区内显示居中的灵动岛。它是临时状态入口，不取代魔法棒和 `/777` 主入口。

灵动岛显示：

- 左侧只显示一次待审核数量。
- 已完成、运行中和失败的简要状态。
- 整个灵动岛均可点击，右侧只用无底色箭头提示可以进入审核，不嵌套文字按钮或重复数量徽标。
- AI 审核运行时的克制进度动画。

点击灵动岛直接重新打开统一审核弹窗。所有待审核事项解决或整轮生成取消后，灵动岛自动隐藏。

视觉与动效要求：

- 桌面端最大宽度约 390px，移动端宽度不超过视口减去 24px。
- 使用接近黑色的高对比主体、青绿色进度和暖色失败提示，与插件现有深浅主题协调。
- 新失败到达时只执行一次短促提醒，不持续跳动。
- 弹窗关闭到灵动岛出现使用 180-220ms 位移、缩放和透明度过渡。
- 尊重 `prefers-reduced-motion`。
- 通过 `env(safe-area-inset-top)` 避开安卓刘海和系统状态栏。
- 不遮挡酒馆顶部主要按钮；若宿主顶部安全区不足，适配器下移到首个无遮挡位置。

## 11. 任务反馈与 Debug

任务页按本轮生成显示：

```text
酒馆命中 8
规则通过 4
过滤排除 4
拆分任务 2
缓存命中 1
运行中 1
待审核 1
输出：A 数据区成功 / TT 等待汇合
```

Debug 记录：

- 当前角色卡和自动识别的世界书。
- 每个规则的命中、通过和排除条目。
- 失效 UID。
- 子 AI 输入来源和显式跨 AI 权限。
- 输出路由及每个目标的结果。
- 数据版本创建、切换和回滚。
- 原始条目保留/替换决策及冲突。
- 汇合屏障的未完成分支。
- 审核优先级、AI 审核、人工操作和重 Roll 历史。
- 灵动岛显示和清空原因。

## 12. 错误处理

- 当前角色没有自带世界书：不派发世界书任务，显示明确空状态。
- 规则引用已删除 UID：跳过失效引用，提示修复规则，不影响其他条目。
- 过滤结果为空：不创建空任务，任务页显示“规则未通过任何命中条目”。
- 子 AI 失败：其他任务继续，失败包进入审核流程，原始条目保留。
- 某个输出路由失败：保留其他路由成功状态，失败路由可单独重试；必需路由失败时进入审核并继续阻塞汇合，非必需路由失败只记录警告。
- TT 注入结果不可用：对应原文不得移除。
- AI 数据存储失败：不切换当前版本，保留失败记录并进入审核。
- 宿主不支持异步等待扫描事件：禁用自动汇合并显示兼容性错误。
- 整轮生成被取消：取消尚未开始的任务，运行中任务按适配器能力终止或丢弃结果，不调用 TT 最终生成。

## 13. 测试策略

### 13.1 纯逻辑测试

- 包含模式求交集。
- 排除模式求差集。
- 包含空集合和排除空集合。
- 只接受当前角色卡世界书条目。
- 条目改名、删除和 UID 失效。
- 同一规则被多个子 AI 复用但任务和输出保持隔离。
- Token 分批只接收过滤后的条目。
- 原始条目“保留优先”冲突决策。

### 13.2 设置与存储测试

- 旧设置迁移到“全部条目”内置规则。
- 自定义规则和子 AI 引用合并。
- 多目标输出。
- 跨 AI 显式读取授权。
- 版本创建、当前指针更新和回滚。
- 单个输出目标失败不回滚其他成功目标。

### 13.3 调度与审核测试

- 并发任务中单个失败不暂停其他任务。
- 有未解决审核时汇合屏障不释放。
- 人工优先和 AI 优先流程。
- AI 审核弹窗开关。
- AI 审核再次失败后强制人工审核。
- 逐条重 Roll、补充说明重 Roll、跳过。
- 全部重 Roll、全部跳过和取消整轮生成。
- 失败尝试历史不被覆盖。

### 13.4 UI 测试

- 搜索结果范围内的全选和反选。
- 搜索隐藏条目的选择状态保持。
- 桌面与 390px 安卓布局无横向溢出。
- 弹窗关闭后灵动岛出现。
- 点击灵动岛重新打开审核弹窗。
- 队列清空后灵动岛自动隐藏。
- 深色、浅色和减少动效模式。
- 灵动岛不遮挡酒馆顶部交互元素。

## 14. 验收标准

- 插件只处理当前角色卡自带世界书，不显示自定义世界书选择器。
- 用户可以创建、编辑、删除和复用条目级包含/排除规则。
- 搜索、全选和反选严格作用于当前搜索结果。
- 子 AI 预设可以组合提示词、世界书规则、其他 AI 数据输入和多个输出目标。
- 默认数据隔离，只有显式配置才允许跨 AI 读取或写入。
- 写回数据创建新版本并支持回滚。
- 并发任务全部解决前不会调用 TT 最终生成。
- 单个任务失败不阻塞其他任务执行，并进入配置的人工或 AI 审核流程。
- 审核弹窗提供逐条和批量重 Roll、补充说明重 Roll、跳过和取消操作。
- 手动关闭审核弹窗后出现美观、响应式的顶部灵动岛，可重新进入审核。
- 跳过或失败未解决的条目保留酒馆原文；TT 注入不可用时不移除原文。
- Debug 能解释条目过滤、任务汇合、审核决策、版本写入和最终提示词来源。
